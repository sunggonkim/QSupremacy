\section{Related Work}

\noindent\textbf{Quantum simulation and NISQ systems.}
Large-scale quantum circuit simulators such as ScaleQsim and AURORA-Q show how HPC systems can extend full state-vector simulation through distributed execution, GPU acceleration, tiered memory, and asynchronous data movement~\cite{scaleqsim,auroraq}. \cuQuantum provides optimized GPU primitives for these measurements~\cite{cuquantum}. NISQ-era studies show both the promise and the limits of current devices~\cite{preskill2018quantum}. \SystemName uses this simulation substrate for a different question: not which simulator is fastest, but what hardware and quality threshold would let a quantum-circuit application beat a native HPC application.

\noindent\textbf{Benchmark suites and application evaluators.}
SupermarQ, QASMBench, MQT Bench, and QAOAKit provide reusable circuits, metrics, and QAOA parameters for comparing devices, compilers, and simulators~\cite{supermarq,qasmbench,mqtbench,qaoakit}. \SystemName is complementary: it wraps application instances with native baselines, end-to-end runtime breakdowns, and a same-quality break-even test.

\noindent\textbf{Quantum applications and native baselines.}
Quantum kernels, variational classifiers, VQE-style chemistry, QAOA-style optimization, and Hamiltonian simulation are common candidates for practical advantage~\cite{biamonte2017quantum,cerezo2022challenges,kandala2017hardware,farhi2014qaoa,georgescu2014quantum,daley2022practical}. These studies motivate application-level comparisons, but each domain also has strong native baselines and different quality metrics. This makes the comparison a systems problem, because runtime, quality, application overhead, and workload scale must be measured together. It also makes one workload insufficient for evidence. \SystemName therefore compares each quantum-circuit path against native ML, chemistry, optimization, and simulation paths under the same workload and target quality~\cite{scikit-learn}.

\noindent\textbf{Fault tolerance and hardware realism.}
Fault-tolerant quantum computing work shows that logical cost depends on surface-code distance, cycle time, lattice-surgery layout, magic-state factories, and decoder latency~\cite{litinski2019game}. \SystemName does not validate such a stack; it reports the measured application threshold that any future hardware model must satisfy.
