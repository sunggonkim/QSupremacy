\section{Related Work}

\noindent\textbf{Quantum simulation and NISQ systems.}
Large-scale quantum circuit simulators such as ScaleQsim and AURORA-Q show how HPC systems can extend full state-vector simulation through distributed execution, GPU acceleration, tiered memory, and asynchronous data movement~\cite{scaleqsim,auroraq}. \cuQuantum provides optimized GPU primitives for these measurements~\cite{cuquantum}. Quantum supremacy and NISQ studies show both the promise and the limits of current devices~\cite{arute2019quantum,preskill2018quantum}. \SystemName uses this simulation substrate for a different question: not which simulator is fastest, but what hardware and quality threshold would let a quantum-circuit application beat a native HPC application.

\noindent\textbf{Quantum applications and native baselines.}
Quantum kernels, variational classifiers, VQE-style chemistry, QAOA-style optimization, and Hamiltonian simulation are common candidates for practical advantage~\cite{biamonte2017quantum,cerezo2022challenges,kandala2017hardware,farhi2014qaoa,georgescu2014quantum,daley2022practical}. These studies motivate application-level comparisons, but each domain also has strong native baselines and different quality metrics. This makes the comparison a systems problem, because runtime, quality, application overhead, and workload scale must be measured together. It also makes one workload insufficient for evidence. \SystemName therefore compares each quantum-circuit path against native ML, chemistry, optimization, and simulation paths under the same workload and target quality~\cite{scikit-learn}.
