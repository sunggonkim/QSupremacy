\section{Introduction}

Quantum computing targets machine learning, chemistry, optimization, and scientific simulation, but executing a circuit is not application-level quantum advantage~\cite{preskill2018quantum,supermarq,qedcbench}. The circuit application must beat a valid native HPC implementation on the same input and at the same output quality after encoding, repeated evaluations, measurement, classical optimization, and postprocessing. For an architect, the central problem is therefore to identify whether the limiting resource is algorithmic quality, logical execution, synthesized rotations, useful shot parallelism, decoder/control reaction, physical space, or the moving native deadline.

Leadership systems provide a way to study this boundary before large fault-tolerant machines exist. \cuQuantum, ScaleQsim, and AURORA-Q expand the circuit scale and throughput that HPC can inspect~\cite{cuquantum,scaleqsim,auroraq}. Their performance is not future-QPU performance. A faster state-vector kernel can leave the complete circuit path behind a native solver, and it says nothing about code distance, finite shots, factory space, or output quality. A defensible study must therefore separate measured evidence cost, $T_{\mathrm{qsim}}/T_{\mathrm{native}}$, from projected hardware cost, $T_{\mathrm{qhw}}/T_{\mathrm{native}}$, while keeping both attached to the same application record.

Figure~\ref{fig:intro-gap} exposes the problem rather than the answer. Required simulator speedup spans 65$\times$--287,046$\times$, but the ratio alone cannot identify a QPU target. The native solver sets a workload-specific deadline; the circuit path adds a workload-specific quality gap and repetition structure; and the physical stack can move its bottleneck after one resource improves. \SystemName converts this paired boundary into five explicit outputs: whether the output is valid, which resource to improve first, how much it must improve, which resource becomes next, and the maximum benefit of improving each resource.

The evidence must also separate verifiability from width. Exact 4--20-qubit records close an auditable loop among a native answer, executable circuit, and natural-unit quality. Such scales remain common in end-to-end QML and chemistry studies, which use two-to-seven-qubit learning circuits or reduced five-to-fourteen-qubit active spaces~\cite{yang2023endtoendqml,domingo2024temporalqml,weaving2025nitrogen}. Wider 100--127-qubit Ising and shallow-QAOA demonstrations establish processor capability, not same-input advantage over native HPC~\cite{kim2023utility,pelofske2024shortqaoa}. We use 36--40-qubit distributed runs only to validate simulator capacity and use deployment-facing CIFAR-10, all-electron CCSD(T), MaxCut, and matrix-free Krylov paths to tighten the native boundary. Neither qubit count nor GPU count is treated as advantage evidence.

They do not jointly bind direct application quality, a measured same-input native deadline, case-level reliability, and first-to-next component marginal utility.

\noindent\textbf{Key Idea.}
\SystemName uses leadership-class HPC as an empirical oracle for deciding which QPU resource delivers the next unit of application-level progress. One record preserves the input, native deadline, output tolerance, circuit demand, finite-shot evidence, dependency schedule, and provenance. The inversion first rejects records without a same-record full-loop quality pass. It then derives case-level distance and rotation precision, prices factory, logical, decoder, host, and space terms under explicit overlap bounds, and recomputes the complete model after each resource improves. Published mechanisms enter only by replacing matched events; their reported average speedups are never borrowed as universal multipliers.

This paper makes three contributions. First, it defines a quality-first paired boundary that distinguishes measured, projected, conditional, and deployment evidence and prevents a quality-failing family from receiving an application-level hardware target. Second, it introduces a component-preserving critical-path inversion that combines workload-valid ready widths, finite shots, application failure budgets, code distance, rotation synthesis, factory footprint, decoder reaction, joint design coverage, and the maximum end-to-end gain from each component. Third, an auditable Perlmutter campaign produces 3,552 records across 222 structural configurations and 16 seeds per configuration, plus direct quality-cost and deployment-facing frontiers. Only 12 finite-shot Sim. records close the complete application contract. Their strict surface-code envelope remains T-state-supply-limited until 2.52--2.75 million parallel factories, after which shot parallelism or logical-gate latency dominates. A matched LSQCA replacement further shows how a published architecture can be rejected for this phase: it saves no core cells at 4--7 logical qubits and matched movement eliminates all runtime-favorable cases.
